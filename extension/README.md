# Расширение для Chrome — аналитика поверх YouTube

Локальная замена панелям vidIQ / NexLev: те же метрики, но данные берутся из
вашего собственного бэкенда `niche-finder`, а не из чужого облака. Наружу
расширение не ходит вообще — только на `127.0.0.1`.

## Что показывает

**Страница ролика** (правая колонка):

* множитель-выброс относительно медианы последних роликов канала того же
  формата (Shorts сравниваются с Shorts) с падением на пожизненное среднее
  канала, если истории мало — это метрика NexLev;
* просмотры в час за последние 24 часа по нашим же снапшотам, ускорение
  (сутки против недели), просмотры на подписчика, вовлечённость;
* прогноз просмотров к 30-му дню по кривой созревания и оценка дохода;
* теги ролика — списком и одной кнопкой в буфер;
* кнопки «собрать канал», «отслеживать», ссылка в дашборд.

**Страница канала** (под шапкой): подписчики, средние просмотры на ролик,
оценка роста и импульс, прогноз дохода, лучшие выбросы канала, лучшее время
публикации в вашем часовом поясе, фразы в заголовках, дающие выбросы, и
похожие каналы. Разделы ниже первого блока появляются, когда в базе есть
хотя бы 5 роликов канала — до этого достаточно нажать «Собрать канал».

**Списки видео** (поиск, главная, рекомендации, вкладка канала): значок с
множителем на превью. Цвет соответствует силе выброса.

## Установка

1. Запустите бэкенд проекта, если он ещё не поднят:
   `make dev` (без Docker) или `docker compose up -d postgres web`.
   Проверить: <http://127.0.0.1:8080/api/health>.
2. Откройте `chrome://extensions`, включите «Режим разработчика».
3. «Загрузить распакованное расширение» → выберите папку `extension/`.
4. Откройте любое видео на YouTube. Панель появится в правой колонке.

Если у иконки расширения красный значок `!` — бэкенд недоступен: проверьте,
что он запущен, и адрес в настройках расширения совпадает с портом (по
умолчанию `http://127.0.0.1:8080`).

## Настройки (по клику на иконку)

| Настройка | Что делает |
|---|---|
| Адрес бэкенда | если поменяли `WEB_PORT`, впишите новый адрес |
| Добирать из YouTube API | ролика нет в базе — дотянуть его одним запросом (1 unit) и сохранить. Выключите, чтобы работать строго по накопленной базе |
| Значки на карточках | множители на превью в списках |
| Только выбросы | значок появляется от ×1,5 и выше |

## Сколько это стоит по квоте

Дозагрузка одного ролика — 1 unit (`videos.list`), плюс 1 unit на канал,
если он неизвестен (`channels.list`). Значки в списке — 1 unit на каждые 50
роликов. Для сравнения, один `search.list` стоит 100 units, а дневной лимит
— 10 000. Всё добранное складывается в тот же Postgres, поэтому повторный
просмотр той же страницы уже бесплатный: ролик перечитывается из базы, пока
не устареет (6 часов), канал — сутки. Кнопка ⟳ в шапке панели заставляет
перечитать принудительно.

Кнопка «Собрать канал» дороже: она обходит uploads-плейлист (1 unit на 50
роликов + 1 unit на 50 видео), поэтому вынесена в явное действие.

## Как устроено

```
content.js     панели и значки, ничего не знает о сети
     |  chrome.runtime.sendMessage
background.js  единственная точка выхода в сеть + кэш ответов
     |  http://127.0.0.1:8080/api/inspect/*
backend/application/inspection.py
     |  сначала Postgres, при промахе — точечный запрос к YouTube Data API
```

Почему сеть только в service worker: страница YouTube отдаётся по https, и
запрос к `http://127.0.0.1` из контекста страницы браузер считает смешанным
контентом. У расширения свой origin, и с `host_permissions` этот запрос
проходит штатно.
